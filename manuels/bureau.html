Principe : le téléphone est maître de ses lots, le Sheet est la copie de référence du bureau. Le bureau lit, valide les ventes, diffuse le référentiel, mais ne modifie pas un lot de technicien (sauf son point GPS, voir 5.3).

2. Mise en place et mise à jour du script du Sheet

2.1 Première installation

  1. Dans le Sheet : Extensions › Apps Script, coller le contenu de sync.gs, renseigner les deux constantes CLE (clé terrain maître) et CLE_BUREAU (clé bureau maître) par des valeurs longues et secrètes.
  2. Déployer › Nouveau déploiement › Application web : exécuter en tant que moi, accès Tout le monde. Copier l'URL se terminant par /exec.
  3. Sur le poste bureau : ouvrir l'application, Paramètres › URL du script et Clé bureau, puis « Charger le référentiel du Sheet ».

2.2 Mettre à jour le script (nouvelle version)

  1. Récupérer sync.gs sur GitHub (la première ligne indique la version), remplacer le code dans Apps Script en conservant vos constantes CLE / CLE_BUREAU.
  2. Déployer › Gérer les déploiements › crayon › Version : Nouvelle version › Déployer. L'adresse /exec ne change pas : rien à refaire sur les téléphones.

Version 3.0 : action setLotGps (point GPS d'un lot placé depuis le bureau). Les colonnes ajoutées par l'application (proprietaire, grille_client, prix_vente_m3, montant_vente) se créent d'elles-mêmes à la première sauvegarde.

2.3 Mettre à jour l'application

Les fichiers de l'application sont publiés sur GitHub Pages : une modification sur main est en ligne en une à deux minutes. Les téléphones prennent la nouvelle version à la prochaine ouverture avec du réseau (le numéro de version est affiché en bas de l'accueil). Le mode vocal (dossiers vendor/ et models/) n'est téléchargé qu'à la première activation.

4. Clés d'accès et configuration des téléphones

Une clé = un technicien (rôle terrain) ou un poste bureau (rôle bureau, qui valide les ventes et voit tout le stock). L'opérateur attaché à la clé est imposé sur toutes les lignes que ce téléphone envoie : c'est lui qui identifie l'auteur d'un lot.

4.1 Créer une clé et équiper un téléphone

  1. Application › Bureau › Clés d'accès › opérateur (prénom ou initiales), rôle › Créer la clé et le lien.
  2. Envoyer le lien de configuration affiché (copier ou partager) au technicien : il l'ouvre une fois dans Safari / Chrome, puis ajoute l'application à l'écran d'accueil. Sur iPhone, le lien peut devoir être collé dans Paramètres › « Coller le lien de configuration ».

4.2 Téléphone perdu, départ d'un technicien

  • Remplacer (tél. perdu) : crée une nouvelle clé pour le même opérateur et désactive l'ancienne ; envoyer le nouveau lien. Sur le nouveau téléphone, Paramètres › « Récupérer mes lots depuis le Sheet » ramène ses lots sauvegardés.
  • Désactiver : la clé ne permet plus ni sauvegarde ni mise à jour ; les données déjà sur le Sheet restent.
Les clés maîtres du script (CLE, CLE_BUREAU) fonctionnent toujours et ne sont pas visibles dans l'onglet CLES : ne les diffusez pas aux techniciens. Seule la clé bureau maître peut vider les lots du Sheet.

5. L'espace Bureau de l'application

Visible sur l'accueil quand une clé bureau est configurée. Charger le stock lit le Sheet (réseau) ; la lecture est conservée sur le poste.

5.1 Stock bord de route

Tous les billons connus du Sheet, groupés par chantier, avec filtres : en stock, proposés (à valider), vendus, recoupés ; par essence ; recherche libre (chantier, n°, opérateur, date). Les montants affichés utilisent les grilles propriétaire des lots.

5.2 Lots clients de l'entreprise

Tous les lots clients transmis par les téléphones, avec statut (brouillon, transmis, vente validée, annulé). Ouvrir un lot : billons, volumes, prix, puis Valider la vente ou Repasser en brouillon / annuler. Le technicien voit le nouveau statut à sa prochaine mise à jour. Un billon vendu ne peut plus être proposé à un autre client ni supprimé sur le téléphone.

5.3 Lots des techniciens

Charger les lots depuis le Sheet : copies en lecture seule des lots de tous les téléphones. Pour chaque lot : listing, récapitulatif (achat / vente / marge), PDF interne, Excel, bordereau propriétaire et bordereau client. Le point GPS peut y être placé ou corrigé sur la carte depuis le bureau : il est écrit sur le Sheet (script 3.0).

Un point GPS placé depuis le bureau sera écrasé si le technicien renvoie ensuite ce lot depuis son téléphone (qui n'a pas le point). À faire sur des lots terminés, ou demander au technicien de le placer lui-même.

5.4 Lot client multi-techniciens (ramasse)

Après chargement des lots des techniciens, crée un lot client à partir des billons de plusieurs téléphones et de plusieurs chantiers (billons par n° ou plage, recoupes, prix de vente). Validé directement avec la clé bureau. Le bordereau de réception client indique le chantier d'origine de chaque billon et un lien GPS par chantier.

5.5 Grilles de prix communes

Bureau › Grilles de prix communes › + Grille commune grumes (ou sur pied) : saisie ligne par ligne puis Enregistrer sur le Sheet (onglet GRILLES). Diffusée à tous les téléphones à leur prochaine mise à jour. Une grille commune supprimée disparaît des téléphones ; les copies locales dans les lots sont conservées.

6. Grilles de prix : propriétaire, client, catalogue et copies locales

NiveauGrille propriétaire (achat)Grille client (vente)
Lot de cubageUne grille : catalogue ou copie propre au lotUne grille par défaut : catalogue ou copie propre au lot
Sous-lot (destination client)—Facultative, l'emporte sur celle du lot : catalogue ou copie propre au sous-lot
Lot client (vente de billons)—Grille du client : catalogue copiée dans le lot et complétée
  • Catalogue = grilles communes du Sheet (préfixe interne sheet-) ou grilles créées sur le téléphone. Modifier une grille catalogue change tous les lots qui l'utilisent sans copie.
  • Copie locale = grille figée dans le lot (ou le sous-lot), modifiable par le technicien pour ce lot seul : prix négocié, client qui change son prix lot par lot.
  • Règles de prix : essence, qualité, Ø min / Ø max (bornes incluses, sur le diamètre cubé), prix €/m³ ; champ vide = toutes ; la ligne la plus précise l'emporte. Un billon sans règle apparaît « sans prix » et n'est pas compté dans les montants.
  • Le Sheet reçoit, par billon, le prix propriétaire (prix_m3, montant) et le prix client (prix_vente_m3, montant_vente), ainsi que les noms des grilles du lot (grille, grille_client).
Convention de nommage conseillée pour les grilles communes : « Achat … » pour les grilles propriétaire, « Vente … » pour les grilles client, avec l'année ou la saison.

8. Les données des lots dans le Sheet

Chaque sauvegarde d'un lot remplace toutes ses lignes (clé lot_id) dans les onglets suivants. Les en-têtes sont créés automatiquement ; ne pas renommer les colonnes.

OngletContenu
LOTUne ligne par lot : type, n° chantier Xylolink, chantier, propriétaire, commune, dépt, GPS (lat, lon, précision), date, opérateur, tarif et mode (sur pied), grille, grille_client, volume, dernière modification.
SOUS_LOTSous-lots du lot : nom, client, grille.
GRUME / BILLONBillons bord de route : n° (grume.rang), essence, qualité, longueur, diamètre, réductions, dimensions cubées, classe, volume, sous-lot, client, grille et prix propriétaire, grille et prix client, date et heure de saisie.
ARBRE / TRONCONEstimation sur pied : tiges (essence, diamètre, classe, tarif, effectif, hauteur, volume) et tronçons de qualité.
RECOUPEBillons recoupés dans un lot client : billon d'origine et tronçons obtenus.
LOT_JSONCopie intégrale du lot (en plusieurs parts) : c'est elle qui permet « Récupérer mes lots » et « Lots des techniciens ». Ne pas modifier.
LOT_CLIENT / LOT_CLIENT_LIGNELots clients : client, date, référence, statut, validation (date, par), volume, montant, json ; et une ligne par billon vendu (clé du billon, origine).

Pour un contrôle ou un rapprochement Xylolink, l'onglet BILLON suffit : une ligne par billon avec chantier, volume et prix. Les exports Excel de l'application reprennent les mêmes données lot par lot.

9. Maintenance, sauvegardes et dépannage

9.1 Sauvegardes

  • Le Sheet est sauvegardé avec le Drive SBF (historique des versions Google + sauvegarde journalière). Faire une copie du Sheet avant toute opération de purge.
  • Chaque téléphone peut produire une copie de secours complète : Paramètres › Exporter tout (JSON), à déposer sur le Drive ; Importer un fichier JSON la restaure.

9.2 Vider les lots du Sheet (fin de saison, test)

Paramètres (poste bureau, clé bureau maître uniquement) › Maintenance du Sheet › Vider les lots du Sheet…, confirmation par le mot VIDER. Supprime lots, billons et lots clients de tous les téléphones sur le Sheet ; essences, qualités, grilles et clés sont conservées. Les téléphones gardent leurs lots et les renverront à leur prochaine sauvegarde : archiver ou supprimer les lots sur les téléphones avant.

9.3 Dépannage

SituationVérification / action
« clé refusée »Clé désactivée ou mal copiée : Bureau › Clés d'accès ; renvoyer le lien de configuration.
« Script du Sheet à mettre à jour (version x) »Le script déployé est plus ancien que l'application : chapitre 2.2.
Un technicien ne voit pas une grille communeVérifier l'onglet GRILLES (type grumes / pied, code identique sur toutes les lignes) ; lui faire « Mettre à jour depuis le Sheet ».
Lot en double sur le SheetUn lot envoyé à un collègue puis modifié sur les deux téléphones : le dernier sauvegardé écrase l'autre (même lot_id). Demander qui a la main (« Reprendre la main »).
Billon « indisponible » lors d'une venteDéjà vendu ou recoupé dans un autre lot client validé : voir Stock bord de route › Vendus / Recoupés.
Bordereau sans la grille attendueLe bordereau propriétaire ignore les grilles client (et inversement). Vérifier Grilles du lot, ou la grille du sous-lot.
Point GPS absent dans un bordereauLe lot n'a pas de point : le placer sur la carte (téléphone ou Bureau › Lots des techniciens, script 3.0).
Modifier le logo ou les mentions légalesFichier docs.js du dépôt GitHub : constante SBF (textes) et SBF_LOGO (image JPEG en base64, 720 px de large).
